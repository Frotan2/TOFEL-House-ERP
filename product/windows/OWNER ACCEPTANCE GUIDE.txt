TOEFL HOUSE ERP - OWNER ACCEPTANCE GUIDE
========================================
ENGINEERING CANDIDATE ONLY - NOT APPROVED FOR LIVE STUDENTS OR FINANCES

This is the ONE short checklist for the Owner's own Windows PC. It covers
only what has NOT already been proven on that PC. Opening this guide does
not install, activate, back up or restore anything. Use synthetic records
only: invented names, invented amounts, no real student information.

ALREADY PROVEN - DO NOT REPEAT
------------------------------
The following passed on the HP ENVY or in the provider's tests and are kept
as evidence. Repeat one only if a step below fails in that same area:
  * Install, sign-in, Stop / Start, reboot persistence and Repair.
  * Placement, admission, enrollment, classes, attendance, marks,
    published grade and completion for a practice learner.
  * Tuition bills, cashier receipts, cash close and Finance handover.
  * Book shop sale, return and stock; refunds; teacher pay and payroll.
  * Role sign-ins with refusal of other roles' screens, and branch and
    company separation.
  * Encrypted backup to a separate drive and restore into a separate
    practice database (on an earlier version).

PRESERVATION - IMPORTANT FIRST
------------------------------
  * DO NOT reinstall, reset passwords, or delete product\data, Docker
    volumes, secrets or existing backups.
  * DO NOT restore over the existing site. DO NOT create or delete Owner
    recovery keys outside the steps below.
  * If any step reports BLOCKED or NOT VERIFIED, keep that status. Do not
    bypass it, and never grant Administrator or disable a check to make a
    step pass. Write down the exact message and stop.

STEP 1 - SAFE CHECK (5 minutes, changes nothing)
------------------------------------------------
[ ] 1. Open "TOEFL House ERP" and click "Check This PC".
[ ] 2. Record the Windows version, Docker response, free disk space and any
        safety warning. The report is information, not approval.

STEP 2 - INSTALL THIS VERSION (about 20 minutes)
------------------------------------------------
[ ] 3. In the launcher click "Check for Updates", then "Install Update".
        The updater checks for a fresh encrypted backup and keeps the
        previous version for rollback. It tells you which signed approval
        it needs; it changes nothing until that approval is present.
[ ] 4. If it stops, follow the on-screen recovery steps. Do not reinstall
        or delete anything; send the step number and message to support.
[ ] 5. Sign in. The sign-in page and screens show The TOEFL House red and
        white colours and logo.

STEP 3 - NEW SCREENS, ONE PASS PER ROLE (about 30 minutes)
----------------------------------------------------------
Sign in as each practice user in turn. Each line should take a minute or two.
[ ] Logo. The sign-in page, the desk and one printed practice receipt show
        the TOEFL House logo and its red. The launcher window shows it too
        after a fresh install.
[ ] 6. Course Owner - Configuration, "Course Owner Policy Controls", Class
        Operations: record the class rules. "Holidays and Closures": add a
        practice holiday. Generating sessions over that date skips it.
[ ] 7. Reception - search a practice student, "Add to a class waiting
        list", then "Remove from waiting list" on "Class waiting lists".
[ ] 8. Academic Manager - Academic desk, "Class changes": approve one
        practice class change and deny another; offer and admit a waiting
        student; approve and revoke an extra seat.
[ ] 9. Academic Manager - Course assessment: open a published practice
        book, "Correct published result" with a reason. The old result
        stays in history as superseded.
[ ] 10. Finance Officer - "Outstanding receivables": "Request correction"
         on a practice bill. A DIFFERENT approver approves or denies it on
         "Correction queue". "Placement fees to bill": issue one fee.
[ ] 11. General Manager - "Progression decisions not yet recorded": record
         one override with a reason.
[ ] 12. Sign in as a user without these roles: the buttons above are not
         shown, and a user limited to one branch sees only that branch.

STEP 4 - BACKUP AND RESTORE ON THIS VERSION (Owner and support together)
------------------------------------------------------------------------
Do this only when the Owner lifts the backup HOLD in writing.
[ ] 13. Owner completes Backup & Recovery in Configuration and turns
         Backup On. Click "Backup" and confirm a verified receipt on the
         separate backup drive.
[ ] 14. With support, restore that backup into a SEPARATE practice
         database using the existing two-person recovery approval. Check
         that the practice records from Step 3 are present. Never restore
         over the live site.

STEP 5 - ACTIVATION FOR REAL USE (Owner decision)
-------------------------------------------------
Only after Steps 1-4 pass and the Owner decides to start real work:
[ ] 15. The Owner and the General Manager each sign the activation request
         on their own signing computer, as set up in the installer. Then run
         "Activate TOEFL House ERP". It refuses without both signatures, a
         fresh verified backup and the verified installation.

NOT REQUIRED FOR INTERNAL USE
-----------------------------
  * Paid publisher code signing and clean-host certification are for
    selling the product to others. This PC uses the provider-verified
    package and the signed update path instead.
  * Tailscale or private HTTPS is needed only if staff use the ERP from
    other computers. On this PC alone the ERP stays at 127.0.0.1.

WHAT TO SHARE - AND WHAT NEVER TO SHARE
---------------------------------------
Share the step number, the on-screen message and redacted screenshots.
NEVER send Administrator credentials, db.env, private recovery keys, real
student information, raw backups or raw logs.

RELEASE DECISION: NO-GO until Steps 1-4 pass on this PC and the Owner
explicitly approves activation. Green GitHub tests, a successful sign-in
or this guide do NOT by themselves authorize real-world operation.
