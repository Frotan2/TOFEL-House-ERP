# PDF-stack reachability trace (SEC-DEPS-01 risk precision, 2026-09-19)

Traced against pinned Frappe
**v16.33.1** (`988e54f3c4c291e2077a83809663f123731abe76`), the framework
version in `foundation-version-matrix.json`, via a local shallow clone
plus the GitHub contents API. ERPNext refs checked at pinned **v16.34.2**;
Education has zero `pdfkit` references (code search, 2026-09-19).

This note sharpens the *risk* of four advisories. It changes no gate:
SEC-DEPS-01 counts advisory matches on pinned trees, and the verdict
stays **REJECT** per
`../phase-2/dependency-remediation-candidate-assessment-2026-09-19.json`.

## pdfkit HIGH (GHSA-9g3x: JS execution + local file exfiltration via `from_string`)

**Mitigated by framework configuration — both exploit halves disabled at
the only runtime call site.**

- The only non-test `pdfkit` call in Frappe v16.33.1 is
  `frappe/utils/pdf.py:123`, inside `get_pdf()` (exhaustive `grep -rn
  "pdfkit"` over the pinned tree; the sole other reference is
  `frappe/tests/test_pdf.py`).
- `get_pdf()` forces `options.update({"disable-javascript": "",
  "disable-local-file-access": ""})` **after** `prepare_options()`, so no
  caller passes options that re-enable either half.
- `FrappePDFKit._find_options_in_meta()` returns `{}`: HTML content cannot
  smuggle wkhtmltopdf options back in through `<meta>` tags.
- Input HTML passes through `scrub_urls()` first.
- Call chains: `download_pdf` → `validate_print_permission` →
  `get_print(as_pdf=True)` → `get_pdf`; the whitelisted `report_to_pdf`
  (which takes caller HTML) also routes through `get_pdf`. The non-default
  `chrome` generator path uses hooks, not pdfkit.
- ERPNext's single `pdfkit` reference is a test-only fixture helper
  (`_make_pdf` in `test_bank_statement_import_log.py`); no runtime path.
- R3 hosted checks (`release-read-export-print-paths-denied`, run
  35053305607) additionally prove unauthorized print/download is denied
  on the guarded ledgers.

Residual unknowns (stated, not waived): attacker-influenced HTML reaches
`from_string` **by design** for authorized print; the mitigation rests on
wkhtmltopdf honoring the forced flags and on no other renderer binary in
the server path. The wkhtmltopdf binary itself was not audited here.

## pypdf MODERATE x3 (GHSA-23w6 / GHSA-763m / GHSA-jp53: outline, XForm and TreeObject resource exhaustion)

**Reachable through native PDF upload. Availability impact, no data access.**

- `File.check_content()` (`frappe/core/doctype/file/file.py:477-479`,
  invoked from the File save path at line 777) runs
  `pdf_contains_js(self._content)` on every uploaded PDF.
- `pdf_contains_js` (`frappe/utils/pdf.py:449`) feeds the raw uploaded
  bytes to `PdfReader` and walks the trailer, pages, outlines and object
  graph with **no visited-set, depth limit, or timeout**.
- The other three `PdfReader` sites read server-generated bytes only
  (just-rendered PDFs in `pdf.py:126`, `print_utils.py:101`, and the
  chrome-generator readback in `pdf_generator/page.py:404`).
- Consequence: any role permitted to upload/attach PDF files can submit
  a crafted file that burns worker CPU/memory in `pypdf==6.15.0`. This is
  a denial-of-service exposure, not a confidentiality/integrity one, and
  no in-repo mitigation exists — the upstream fix (6.16.x) is unreachable
  through official Frappe pins.

## WeasyPrint MODERATE x2 (GHSA-jf6q SSRF, GHSA-jhhc CSS injection)

**Gated on beta-builder print formats, which this product does not ship.**

- WeasyPrint renders only via `PrintFormatGenerator.render_pdf()`
  (`frappe/utils/weasyprint.py:102-115`), reached solely when a Print
  Format document has `print_format_builder_beta` set
  (`frappe/utils/print_utils.py:148-164`, `send_print_as_pdf` path).
- This product ships **zero** Print Format fixtures (no
  `print_format_builder_beta` anywhere under `apps/toefl_house/`), and
  default/native formats take the wkhtmltopdf path.
- SSRF would additionally require attacker-influenced content rendered
  into a fetched-URL position (`src`, CSS `url()`) of such a format.
- Operational caveat: a server administrator could create a beta-builder
  format later; that would open this path outside product control.

## setuptools MODERATE (GHSA-h35f: MANIFEST.in NFC/NFD sdist exclusion bypass)

**No runtime trigger in the deploy/operate path.**

- The flaw triggers when *creating* an sdist on macOS. Nothing in the
  Bench install, migrate, or operate path builds an sdist; owned use of
  setuptools is build-system-only (`apps/toefl_house/pyproject.toml`).
- The finding remains counted by the gate (correctly — the installed
  version is in the affected range), but there is no deployment action
  through which it executes.
