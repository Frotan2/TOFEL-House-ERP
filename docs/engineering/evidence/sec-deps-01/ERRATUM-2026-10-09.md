## E6. 2026-10-15 GHSA-vhrc-hgrq-x75r (@tiptap/extension-link) withdrawn from BROWSER_SELF_DENIAL to BLOCKED

The register (2026-09-23) closed this advisory as BROWSER_SELF_DENIAL. Its premise was that a
`javascript:` link injection runs only in the author's own session, because cross-user
exploitation requires server persistence and "sanitize_html strips" that content.

Review on 2026-10-15 found the premise false at the pinned Frappe SHA (988e54f3):

- `frappe/utils/html_utils.py` `sanitize_html` returns its input unchanged when `is_json(html)` is
  true, before nh3 runs.
- `frappe/model/base_document.py` `_sanitize_content` calls `sanitize_html` on every
  HTML-capable field on save, so the short-circuit applies to saved Text Editor values.
- A quoted HTML string such as `"<img src=x onerror=...>"` is a valid JSON string literal. It is
  stored unsanitized. Text Editor fields in education (5), hrms (20), and erpnext (154) are
  writable by any principal with write permission on that doctype, and other users then render
  them.

The register entry is immutable, so the change uses a dated delta
(`advisory-delta-2026-10-15/delta-dispositions.json`) with a `withdraws` action. The loader
honors it only to tighten a record: the target must be a non-closed disposition, and the original
value is kept in `withdrawn_from`. The gate therefore goes red for this advisory until the
exposure is contained and verified.

Containment, unit-verified only: `apps/foundation_security/foundation_security/html_containment.py`
runs on the `validate` doc event for every doctype. It re-sanitizes only values that are valid JSON
and contain `<` or `>`, using `always_sanitize=True`, so Frappe's own pass receives cleaned
content. Tests: `tests/security/test_html_containment_2026_10_15.py`.

Not verified: the containment has not been run against a live Frappe bench. Reinstating a
disposition needs runtime evidence from a hosted run, plus a loader change that records the
reinstatement explicitly. Owner impact: this is an authenticated cross-user stored-XSS class, so
it blocks release until the runtime check passes.
