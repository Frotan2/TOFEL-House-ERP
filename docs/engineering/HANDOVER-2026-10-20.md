## 3. Windows installation and startup

Prerequisite: 64-bit Windows 10 or 11, internet, about 30 GB free, and
[Docker Desktop](https://www.docker.com/products/docker-desktop/) installed
once (its installer is click-through).

1. Open `product\windows` and double-click **Install TOEFL House ERP.cmd**.
   The first build takes 20–60 minutes. It shows the one-time Administrator
   password and opens `http://127.0.0.1:8000`.
2. Follow `product\windows\VALIDATION.md` in order. Its ten lifecycle steps are:
   install, first boot, login, Start, Stop, Start again, Repair, browser login, persistence.
3. Daily use: **Start TOEFL House ERP.cmd** opens the system, **Stop TOEFL House ERP.cmd** closes it.
   Start launches Docker Desktop if it is not running.

The ERP listens only on `127.0.0.1` on that PC. Other staff PCs need the
Tailscale setup in `docs/engineering/LAUNCH-RUNBOOK.md` (section "Multi-user
access"). That path has not been tested on your tailnet.

## 4. Initial administrator and account setup

- Administrator is for first-run setup and recovery only. Keep its password private.
- Create a **separate** enabled System User for the Course Owner, give it the
  native **Course Owner** role, and set its own password. Sign in as that user
  for all policy work. Guarded Owner commands refuse Administrator, by design.
- Other staff get their own users with the matching roles (General Manager,
  Academic Manager, Finance Manager, Reception, Instructor, and duty roles).
  Roles are native Frappe roles; the ERP refuses commands from anyone without the bound role.
- Microsoft sign-in is **optional**. Core login is the username and password
  above. The Office 365 route refuses sign-in unless an owner-configured tenant ID is in
  site configuration (`office_365_tenant_id`) and a Social Login Key is set up. Neither is needed for core use.

## 5. Configuring the eight owner policies

Log in as the Course Owner, open the **ERP Configuration** desk. Every policy
ships **empty and fails closed**: each workflow refuses until you create and
validate the policy. Values are your decisions; engineering supplies no defaults.

| Policy | What you enter | What it controls |
| --- | --- | --- |
| TH Owner Operations Policy | reporting review days, class capacity target, tax, transfers/withdrawals, calendar notice, nightly backup time, backup versions to keep, backup retention behavior, recovery public key, key custody requirement, recovery quorum | **Backup only** is enforced at runtime (time, keep count, behavior, public key). The other fields are recorded decisions with no runtime consumer yet (see section 8). |
| TH Catalog Linkage Policy | advisory or enforcing link between enrollment and the course catalog | Enrollment intake |
| TH Returning Student Policy | rule for linking and reusing a returning student's record | Admission |

| TH Roster Change Policy | last date for mid-term add/move | Class roster changes |
| TH Attendance Correction Policy | approver role and correction window in days | Attendance corrections |
| TH Adjustment Posting Policy | whether orphan adjustments may post | Teacher compensation posting |

## 8. Known limitations and accepted risks

  enforced by any workflow. Tax stays authoritative in native ERPNext.

## 10. Troubleshooting

| Symptom | What to do |
| --- | --- |
| Start says Docker is not running | Wait up to a minute; Start opens Docker Desktop. If it still fails, open Docker Desktop once, then Start again. |
| A step fails and the window shows an error | Double-click **Repair TOEFL House ERP.cmd** once. Retry the step. If it fails again, stop and send the window photo and `data\logs` as a ZIP. |
| Browser shows the login page but login fails for the Course Owner | Check the account has the Course Owner role. Administrator cannot run policy commands. |
| A workflow refuses with "no active ... policy" | Expected while the hold is active. Do not create or validate a policy; wait for an explicit hold-clearance and updated instructions. |
| A policy won't validate with a backup time error | Do not edit or validate policy during the current hold. Record the issue for engineering after the hold is formally cleared. |
| "needs the Course Owner role" | You are signed in as a user without that role. Sign in as the Course Owner. |
| Backup refuses to run | Expected during the preservation/restore hold. Do not retry or change policy; wait for explicit engineering hold-clearance. |
| Anything else | Stop. Do not delete `product\data`. Send the `data\logs` ZIP. |

Never delete `product\data`, never paste a private key into the ERP, and never run
Deactivate or a restore without reading `LAUNCH-RUNBOOK.md`.
